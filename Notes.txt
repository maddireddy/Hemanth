Project Notes - efg-platform-list
================================

This document captures step-by-step instructions for: required software installs, classpath / JAVA_HOME / environment configuration, building the project, running the application (producer + consumer), debugging, and end-to-end testing. Tailored for macOS (zsh) and the current project layout.

1) Prerequisites (software to install)
-------------------------------------
- Java 8 (JDK 1.8) — required for building this project (sourceCompatibility = 1.8).
  - Install using Homebrew (Temurin/CORRETTO) or your JDK manager:

    ```bash
    brew tap homebrew/cask-versions
    brew install --cask temurin8    # or corretto8, adoptopenjdk8, etc.
    ```

- Kafka & Zookeeper
  - Install and run via Homebrew (quick for local dev):

    ```bash
    brew install kafka        # if not installed
    brew services start zookeeper
    brew services start kafka
    ```

  - Alternatively run Kafka + Schema Registry via docker-compose if you prefer containers.

- (Optional) Confluent Schema Registry — if you plan to use Confluent Avro serializers
  - Run via Docker Compose or install Confluent Platform locally.

- kcat (formerly kafkacat) — nice CLI consumer/producer
  ```bash
  brew install kcat
  ```

- jq — helpful to pretty-print JSON in shell
  ```bash
  brew install jq
  ```

2) Environment configuration (JAVA_HOME and PATH)
-------------------------------------------------
- The build and some Gradle/Groovy compiled script classes expect to run under Java 8. Confirm current java:

  ```bash
  java -version
  echo $JAVA_HOME
  /usr/libexec/java_home -V
  ```

- To set Java 8 for the current shell session:

  ```bash
  export JAVA_HOME=$(/usr/libexec/java_home -v 1.8)
  export PATH="$JAVA_HOME/bin:$PATH"
  java -version    # should report 1.8.x
  ```

- To make this persistent add the export lines to `~/.zshrc`.

3) Build the project (Gradle helper)
-----------------------------------
- This repository includes a helper script `gradle7.sh` that downloads/uses Gradle 7.6 to avoid system Gradle issues.

  ```bash
  chmod +x ./gradle7.sh
  ./gradle7.sh clean bootJar --no-daemon
  ```

- Output: `build/libs/efg-platform-list-0.0.1-SNAPSHOT.jar` (or similar).

4) Running the application
--------------------------
There are several convenient ways to run the project depending on what you want to test.

A) Full app (web server + consumer) — producer and consumer in same process

  ```bash
  # ensure JAVA_HOME points to Java 8 (if needed)
  export JAVA_HOME=$(/usr/libexec/java_home -v 1.8)

  # build if needed
  ./gradle7.sh bootJar --no-daemon

  # start app on port 8081 and capture logs
  nohup java -jar build/libs/*-SNAPSHOT.jar --server.port=8081 > app.log 2>&1 & echo $! > app.pid
  tail -F app.log
  ```

  - Watch `app.log` for lines:
    - Producer success: `Message sent to topic efg-platform-list: EfgPlatformList{...}`
    - Consumer receive: `Received EfgPlatformList message: EfgPlatformList{...}`

B) Consumer-only process (no web server) — useful when you want a separate consumer running

  ```bash
  # run the application with no web server so only the consumers run
  nohup java -jar build/libs/*-SNAPSHOT.jar --spring.main.web-application-type=none > consumer.log 2>&1 & echo $! > consumer.pid
  tail -F consumer.log
  ```

C) Run the standalone consumer dump utility (decodes Avro-reflect messages and prints JSON)

  - I added `AvroConsumerDump` and a Gradle task `runConsumerDump`.
  - Usage via Gradle (recommended):

    ```bash
    # after a successful bootJar
    ./gradle7.sh runConsumerDump -PconsumerArgs="efg-platform-list localhost:9092 5" --no-daemon
    ```

    - Arguments: `<topic> [bootstrapServer] [maxMessages]`.
    - The tool will pretty print up to `maxMessages` decoded `EfgPlatformList` JSON objects.

  - Or run directly without Gradle:
    ```bash
    java -cp build/libs/*-SNAPSHOT.jar com.pnc.efg.util.AvroConsumerDump efg-platform-list localhost:9092 5
    ```

5) Publishing a test message (producer)
-------------------------------------
- The REST endpoint to publish is: `POST /api/efg/publish`.
- Example payload (matches item shapes accepted by the service):

  ```bash
  curl -sS -X POST http://localhost:8081/api/efg/publish \
    -H "Content-Type: application/json" \
    -d '{
      "publishDateTime":"2025-12-03T12:00:00Z",
      "sourceSystem":"TEST",
      "items":[
        {"product":"P1","ruleName":"R1"},
        {"product":"P1","ruleName":"R2"},
        {"product":"P2","rules":["R3","R4","R3"]}
      ]
    }'
  ```

6) Verify messages in Kafka
---------------------------
- Quick presence check (raw binary will be printed):

  ```bash
  $(brew --prefix kafka)/bin/kafka-console-consumer --bootstrap-server localhost:9092 \ 
    --topic efg-platform-list --from-beginning --max-messages 5
  ```

- Using kcat (install with `brew install kcat`):

  ```bash
  kcat -C -b localhost:9092 -t efg-platform-list -c 5
  ```

- Human-readable decoding (Avro reflect): either use the running `EfgConsumer` logs that print decoded POJOs or run the `AvroConsumerDump` utility (above). Console consumers will show binary; the dump utility decodes using the same deserializer used by the app.

7) Running tests
----------------

8) Debugging tips
-----------------
- Logs: `tail -F app.log` or `consumer.log` is your primary source.
- Enable debug for Spring Boot to view auto-configuration conditions:
  ```bash
  java -jar build/libs/*-SNAPSHOT.jar --debug --server.port=8081
  ```

- Remote debugging (attach a debugger): start the JVM with debug flags:
  ```bash
  # listen on port 5005, suspend=n
  nohup java -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005 -jar build/libs/*-SNAPSHOT.jar --server.port=8081 > app.log 2>&1 & echo $! > app.pid
  ```
  Then connect from IDE (IntelliJ/Eclipse) remote debugger.

- Check Kafka connectivity issues: broker address, advertised.listeners and firewall. From the app host test:
  ```bash
  nc -vz localhost 9092
  ```

9) Common troubleshooting and fixes
----------------------------------
- "Unsupported class file major version" during Gradle: ensure the Gradle process runs under Java 8 (set `JAVA_HOME` to JDK8) before running `./gradle7.sh`.
- Port 8081 already in use: find and kill process:
  ```bash
  sudo lsof -iTCP:8081 -sTCP:LISTEN -P -n
  kill <PID>
  ```
- Schema Registry 404 when registering schema: confirm the registry is running at the expected port and path (`http://localhost:8081`). If the registry is not running, start it or use Docker Compose. If registry requires auth, supply credentials.
- Messages show as noisy/concatenated in console consumers: this is normal when values are Avro binary. Use `AvroConsumerDump` or a consumer bean to decode.

10) Notes: Avro reflect vs Confluent Avro
--------------------------------------
- Current project uses Avro reflection (custom `AvroReflectSerializer`/`AvroReflectDeserializer`). This serializes/deserializes POJOs using Avro reflection. It's simple for internal services but does not automatically register schemas with Schema Registry.
- If you want Schema Registry-managed Avro with automatic registration and cross-language compatibility, switch to Confluent Avro serializers (`io.confluent:kafka-avro-serializer`) and configure `schema.registry.url`.

11) Useful quick commands summary
--------------------------------

- Start (full): `nohup java -jar build/libs/*-SNAPSHOT.jar --server.port=8081 > app.log 2>&1 & echo $! > app.pid`

- Dump decoded Avro messages: `./gradle7.sh runConsumerDump -PconsumerArgs="efg-platform-list localhost:9092 5" --no-daemon`

12) Windows (PowerShell / CMD) — quick reference
------------------------------------------------
These steps mirror the macOS instructions but use Windows tools and paths. Two recommended ways to run the project on Windows:
- Native Windows (install JDK, Kafka binaries or Confluent platform) and run directly from PowerShell/CMD.
- Use WSL2 (Ubuntu) or Docker Desktop for a Linux-like environment — often easier for Kafka tooling.

Prerequisites (Windows)
- Java 8 JDK (Temurin/Adoptium or Azul/Corretto)
  - Installer: download and run the JDK 8 installer from https://adoptium.net or https://www.azul.com/downloads/.
  - Or use Chocolatey (PowerShell as Administrator):

    ```powershell
    choco install temurin8jdk -y
    ```

- Kafka: download Kafka binaries from Apache (https://kafka.apache.org/downloads) or install Confluent Platform.
  - Alternatively use WSL2 and install Kafka via apt in your Ubuntu instance, or run Kafka in Docker (recommended for parity with Linux).

- kcat (kafkacat) via Chocolatey (optional):
  ```powershell
  choco install kcat
  ```

- jq: use Windows build or use `ConvertFrom-Json` in PowerShell.

Set JAVA_HOME and PATH (PowerShell / CMD)
- Temporary for current PowerShell session:
  ```powershell
  $env:JAVA_HOME = 'C:\Program Files\AdoptOpenJDK\jdk-8.x.x'
  $env:PATH = "$env:JAVA_HOME\bin;${env:PATH}"
  java -version
  ```
- Persistent (System environment variables):
  - Use System Properties GUI or PowerShell `setx`:
  ```powershell
  setx -m JAVA_HOME "C:\Program Files\AdoptOpenJDK\jdk1.8.0_xxx"
  ```
  - Open a new terminal to pick up persistent changes.

Build the project on Windows
- The repo contains `gradle7.sh` (POSIX shell). On Windows you can:
  1. Install Gradle (Chocolatey: `choco install gradle`) and run `gradle clean bootJar`.
  2. Or use WSL2 and run the existing `gradle7.sh` from a Linux shell.
  3. Or use the `./gradle7.sh` via Git Bash / Cygwin if available (ensure `bash` present).

Example PowerShell build (with Gradle installed):
```powershell
gradle clean bootJar
```

Run the application (PowerShell)
- Start the app (full web + consumer):
```powershell
# from project root
java -jar .\build\libs\efg-platform-list-0.0.1-SNAPSHOT.jar --server.port=8081 > app.log 2>&1 &
# or run in foreground
java -jar .\build\libs\efg-platform-list-0.0.1-SNAPSHOT.jar --server.port=8081
```

- Start consumer-only (no web server):
```powershell
java -jar .\build\libs\efg-platform-list-0.0.1-SNAPSHOT.jar --spring.main.web-application-type=none
```

Publishing a test message (PowerShell)
- Use `curl` (Windows 10+ includes curl) or PowerShell's `Invoke-RestMethod`:
```powershell
curl -X POST http://localhost:8081/api/efg/publish -H "Content-Type: application/json" -d '{ ... }'
# or
Invoke-RestMethod -Uri http://localhost:8081/api/efg/publish -Method POST -Body (@'{"publishDateTime":"2025-12-03T12:00:00Z","sourceSystem":"TEST","items":[{"product":"P1","ruleName":"R1"}]} '@) -ContentType 'application/json'
```

Verify messages in Kafka (Windows)
- If you installed Kafka natively, use `bin\windows\kafka-console-consumer.bat` shipped with Kafka:
```powershell
.\bin\windows\kafka-console-consumer.bat --bootstrap-server localhost:9092 --topic efg-platform-list --from-beginning --max-messages 5
```

- Using kcat (if installed via Chocolatey):
```powershell
kcat -C -b localhost:9092 -t efg-platform-list -c 5
```

Run the consumer dump utility on Windows
- After building the jar, run the dump tool just like on macOS (use backslashes or double quotes as needed):
```powershell
java -cp .\build\libs\* ef.pnc.efg.util.AvroConsumerDump efg-platform-list localhost:9092 5
# or using the fully-qualified class
java -cp .\build\libs\* com.pnc.efg.util.AvroConsumerDump efg-platform-list localhost:9092 5
```

Port and process checks on Windows
- See what listens on a port (useful if port 8081 is busy):
```powershell
netstat -ano | Select-String ":8081"
# get PID then show process
tasklist /FI "PID eq 12345"
# kill process
taskkill /PID 12345 /F
```

Debugging and remote attach (Windows)
- Start the JVM with remote debug flags similarly:
```powershell
java -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005 -jar .\build\libs\*.jar
```
Then attach from IDE.

Troubleshooting notes (Windows-specific)
- If Gradle build fails due to Windows path length or CRLF issues, ensure Git autocrlf is off for shell scripts, or run in WSL/Git Bash.
- If you prefer a Linux-like experience for Kafka tooling, WSL2 + Ubuntu is simplest: install JDK8 inside WSL, run `./gradle7.sh` and Kafka there.

End Windows section
