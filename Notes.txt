Project Notes - efg-platform-list
================================

Purpose
-------
These notes describe how to set up the local environment on macOS and Windows, build and run the project (producer + consumer), test the endpoints, and verify messages on Kafka topics. They also document quick troubleshooting and recommended next steps.

Overview of the project
-----------------------
- Spring Boot (2.7.x) application built with Gradle. Target Java 1.8 (sourceCompatibility=1.8).
- Uses Avro reflection serializers/deserializers (no codegen plugin required).
- Topics used:
  - Platform list topic: `efg-platform-list`
  - Alerts topic: `efg-all-alerts`

1) Prerequisites
-----------------
Install these tools before building or running locally.

macOS (recommended)
- Homebrew (https://brew.sh)
- Java 8 (Temurin / Corretto / AdoptOpenJDK)
  - Example (Homebrew Temurin 8):

  ```bash
  brew tap homebrew/cask-versions
  brew install --cask temurin8
  ```

- Kafka (either local brew service or docker-compose). Quick options below.
- kcat (formerly kafkacat):

  ```bash
  brew install kcat
  ```

Windows
- Install a JDK 8 distribution (Temurin/Adoptium, Corretto). Use the installer and set JAVA_HOME.
- Either install Kafka natively, or use Docker Desktop (recommended) and run the docker-compose stack.
- Install kcat via scoop/chocolatey or use Dockerized kcat.

2) Kafka quickstart (two easy ways)
----------------------------------
A) Docker Compose (recommended for isolation)

Create a docker-compose.yml (or use the repository's example if present). A minimal quick stack:

```yaml
version: '3.8'
services:
  zookeeper:
    image: confluentinc/cp-zookeeper:7.3.0
    environment:
      ZOOKEEPER_CLIENT_PORT: 2181
      ZOOKEEPER_TICK_TIME: 2000
  kafka:
    image: confluentinc/cp-kafka:7.3.0
    depends_on:
      - zookeeper
    environment:
      KAFKA_BROKER_ID: 1
      KAFKA_ZOOKEEPER_CONNECT: 'zookeeper:2181'
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://localhost:9092
      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1
    ports:
      - '9092:9092'
  schema-registry:
    image: confluentinc/cp-schema-registry:7.3.0
    depends_on:
      - zookeeper
      - kafka
    environment:
      SCHEMA_REGISTRY_KAFKASTORE_CONNECTION_URL: 'zookeeper:2181'
      SCHEMA_REGISTRY_HOST_NAME: schema-registry
      SCHEMA_REGISTRY_LISTENERS: http://0.0.0.0:8081
    ports:
      - '8081:8081'
```

Start it:

```bash
docker compose up -d
```

Verify Kafka broker:

```bash
kcat -b localhost:9092 -L
``` 

B) Homebrew (macOS) — quick native services

```bash
brew install kafka
# start zookeeper and kafka
brew services start zookeeper
brew services start kafka
```

4) Build the project
--------------------
This repo includes a Gradle wrapper and helper. Prefer the wrapper for reproducible builds.

From the project root:

macOS / Linux / Windows (Git Bash / PowerShell):

```bash
./gradlew clean build --no-daemon
```

If ./gradlew is not executable on macOS, make it so:

```bash
chmod +x gradlew
```

Artifacts: `build/libs/` will contain the jar (e.g., `efg-platform-list-0.0.1-SNAPSHOT.jar`).

5) Running the application
--------------------------
You can run the Spring Boot app in two ways: via the Gradle bootRun task or with the built jar.

- Using Gradle (dev):

```bash
./gradlew bootRun --no-daemon
```

- Using the jar (production-like):

```bash
java -jar build/libs/*-SNAPSHOT.jar
```

Configuration
-------------
The app reads `src/main/resources/application.yml`. Key Kafka properties (defaults) are:

- `app.kafka.bootstrap-servers` — e.g., `localhost:9092`
- `app.kafka.platform-topic` — `efg-platform-list`
- `app.kafka.alert-topic` — `efg-all-alerts`

You can override these with environment variables or command-line `--spring.config.additional-location` if needed.

6) End-to-end: publish a platform-list message
----------------------------------------------
1) Ensure Kafka is running (docker compose or brew services) and app is started.
2) POST to the producer endpoint:

curl (example):

```bash
curl -s -X POST http://localhost:8080/api/efg/publish \
  -H 'Content-Type: application/json' \
  -d '{
    "publishDateTime":"2025-12-03T10:00:00Z",
    "sourceSystem":"SYS",
    "items": [
      {"product":"P1","rules":["r1","r2"]},
      {"product":"P1","rules":["r3"]},
      {"product":"P2","rules":["r4"]}
    ]
  }'
```

3) Verify the message on the topic using kcat or Kafka console consumer:

With kcat:

```bash
kcat -b localhost:9092 -t efg-platform-list -C -o beginning -q
```

Kafka console consumer (from Kafka distribution):

```bash
./bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic efg-platform-list --from-beginning --max-messages 1
```

Note: messages are Avro-reflect binary. To inspect with consumers you need a deserializer or the app's consumer logs; kcat will print binary unless using a schema-aware reader.

7) End-to-end: publish an alert
-------------------------------
POST to alerts endpoint:

```bash
curl -s -X POST http://localhost:8080/api/efg/publish-alerts \
  -H 'Content-Type: application/json' \
  -d '{
    "publishDateTime":"2025-12-03T11:00:00Z",
    "sourceSystem":"SYS",
    "alertId":"ALERT-1",
    "eventTime":"2025-12-03T11:00:00Z",
    "alertType":"TYPE1",
    "severity":"HIGH",
    "message":"Something happened",
    "details":{"key1":"val1"}
  }'
```

Verify consumer logs or use a consumer configured with the Avro reflect deserializer.

8) Tests
--------
Run unit and integration tests:

```bash
./gradlew clean test --no-daemon
```

There is an EmbeddedKafka integration test for the platform flow. If you add the alerts EmbeddedKafka test it will bring up embedded brokers during test.

9) Troubleshooting
------------------
- If Gradle complains about Java version, ensure `JAVA_HOME` is set to a JDK 8 installation (see section 3).
- If push to GitHub fails due to large files in history, ensure you're on the cleaned branch `feature/git-clean-clean`. Use `git status` and `git rev-parse --abbrev-ref HEAD` to confirm.
- If Kafka messages look binary in CLI tools, that's because Avro-reflect uses binary serialization. Use the app's consumer logs or a matching Avro deserializer to decode messages.
